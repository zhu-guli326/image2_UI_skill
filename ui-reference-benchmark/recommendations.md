# Image2 UI 案例库参考结论

调研对象包括 Dribbble、Behance、Awwwards、Codrops、Mobbin、Page Flows、SaaSFrame、Refero 和 Godly。结论不是把案例库改成作品集，而是让它同时具备三种能力：快速找参考、验证真实交互、解释复刻判断。

## 最值得直接借鉴的效果

1. **参考图与成品对照器**

   在现有参考图、视频、Demo 三种预览之外，增加叠层透明度滑块、闪烁切换和差异热图。这个能力与 image2 UI 的“还原”目标直接相关，也比普通设计图库更有辨识度。

2. **流程时间线**

   参考 Page Flows，把一组孤立页面变成一个任务流程。每个步骤包含截图、操作名称、触发方式、状态变化和可播放录屏。优先覆盖 onboarding、搜索、生成、编辑、保存和导出。

3. **多断点对照带**

   同一案例并列展示 desktop、tablet、mobile，标记哪些区块发生重排、裁切、隐藏或交互改写。Behance 长案例经常展示多设备，但可以进一步结构化成可比较视图。

4. **案例详情章节化**

   借鉴 Dribbble 的短段落与大图交替、Behance 的长卷模块，再加入 sticky 目录和阅读进度。推荐固定章节：目标、参考拆解、资产分工、关键页面、流程、状态、响应式、对照、实现说明、验证结果。

5. **按任务检索，而不只按行业检索**

   参考 Refero、SaaSFrame 和 Mobbin，增加 Page Types、Flows、UX Patterns、UI Elements 四组筛选。用户通常不是只想找“健康类 App”，而是想找“健康类 App 的 onboarding、付费墙或结果页”。

6. **交互状态矩阵**

   在详情中统一展示 default、hover、focus、active、loading、empty、error、success 和 disabled。Dribbble 很适合看主画面，但状态完整性才是 image2 UI 可以证明工程质量的地方。

7. **设计决策账本**

   用 `观察/问题 -> 判断 -> 实现 -> 结果` 四列记录关键选择，并标明哪些是原作者说明、哪些是截图事实、哪些是复刻推断。这样案例不只是“做得像”，还能解释为什么这样做。

8. **可解释的还原度评分**

   不使用单一百分比，分别评估布局、字体、颜色、素材、响应式和交互。每项附对照证据，避免评分变成装饰数字。

## 可以形成品牌记忆点的效果

- 卡片 hover 时播放 2 至 4 秒关键交互片段，离开后复位。
- 详情首屏使用设备 mockup，但保持真实屏幕清晰，不用过度透视或暗色遮罩。
- 页面滚动时，左侧参考图固定，右侧逐步切换拆解标注和实现结果。
- 关键 flow 用同步双轨播放：左侧参考录屏，右侧复刻 Demo。
- 资产板使用 provenance 标签区分原图、自制、image2 生成和代码渲染。
- 将相似案例组成 benchmark 集合，如“AI 输入框”“图片上传”“生成结果”“商品详情”“数据 Dashboard”。

## 只建议用于旗舰案例

Awwwards 和 Codrops 上的 WebGL、3D、声音、滚动劫持、终端彩蛋很有记忆点，但性能、移动端和可访问性成本高。建议最多给 1 至 2 个旗舰案例使用，并提供静态或 reduced-motion 降级；不适合作为整个案例库的默认浏览方式。

## 推荐实施顺序

### P0：立即增强信息价值

- 新增页面类型、流程、pattern、设备和可信度筛选。
- 案例详情加入章节导航、流程时间线和状态矩阵。
- 增加 desktop/tablet/mobile 对照。
- 标记真实产品、概念稿、重设计和技术实验。

### P1：建立 image2 UI 的独特证据

- 实现叠层滑块、闪烁切换和差异热图。
- 增加分项还原度评分。
- 展示设计 token、组件和 image2 资产清单。
- 增加案例版本、采集时间和最后验证时间。

### P2：增强传播效果

- 卡片 hover 视频预览。
- 同步双轨录屏。
- 少量滚动转场、3D 或声音实验。
- 失败方案和迭代分支展示。

## 关键判断

当前案例库的视觉卡片已经足够完整，下一阶段不应主要继续增加不同颜色和风格的卡片。最有价值的提升，是把“案例数量”升级成“可检索的界面知识”和“可验证的复刻证据”。
